# 序言

这两年 OPC 这个词被讲得很热闹。One Person Company，一人公司。很多人理解到的版本是：一个人也能开公司，用 AI 当员工，然后就能靠自己的产品或服务赚到钱。

我不觉得这个逻辑站得住。能不能赚到钱，从来不是"有没有用 AI"决定的,而是你的产品和服务有没有对上真正的需求。这本质上还是供需关系,没有需求,供应摆在那儿也没有意义。你的产品卖给谁,你的服务卖给谁,如果这个问题回答不出来,AI 再强也没用。至于什么行业能赚钱、什么赛道值得进,那是漫长的市场考察之后才能回答的问题,不在这本书要讨论的范围里。

我想写这本《OPC Adventure》,是因为我觉得很多人在这个问题上想岔了。AI 能帮你做的第一件事,从来不是帮你去赚钱,而是帮你把 OPC 这套骨架先搭起来——你是谁,你的业务是什么,你打算以什么形象出现在别人面前。

这件事我自己是先经历过一遍的,而且是在 AI 还没怎么介入之前。前两年我原本经营的一家改装厂遇到经营上的危机,几乎面临解散。后来我找到一种重组方式:以我自己为核心,不再招更多人,产品和服务的宣传、自媒体运营、客户沟通、收款分利润都由我一个人对接,具体施工交给合作门店负责。现在回头看,那其实就是一个 OPC 的雏形,只是当时还没有 AI 帮忙,所有事情都得亲力亲为,一个人从获客做到售后,说实话挺累的。这段经历让我很早就知道,开一人公司从来不是"随便想一个产品就能卖出去"那么简单。

我接触 AI 不算晚,2020、2021 年就用过很早期的 GPT。但那时候问出来的答案大多空泛、模棱两可,给不了什么真正有用的指导——一部分是模型本身还在早期,一部分也是我自己还不知道怎么用。真正感觉到不一样,是 2025 年下半年。先是 Gemini 的图像生成能力有了一次明显的跨越 [1],门槛降下来了,给提示词就能出图,不用再忍受一堆瑕疵。同时 NotebookLM 让我第一次感觉到"早期 agent"的样子——喂给它文档,它能按你的要求产出播客、PPT、报告 [2]。再往后,是 OpenAI Codex 和 Claude Code 这一类工具出现 [3][4],用起来又是另一回事了。

我印象最深的一次,是解决 Memos 笔记应用的备份文件问题。它导出的不是可以直接打开的格式,以前我的办法是拿着 AI 给的代码,在对话里复制,粘贴到本地,改扩展名,做脚本,再打开终端跑一遍——很容易出错,也很折腾。用了 Claude Code 这类工具之后,我只需要说清楚我要什么结果,剩下的它自己在后台跑完,最后我拿到的就是一堆整理好的 Markdown 笔记。这是我第一次真切感觉到,agent 和以前的"问答式 AI"不是一回事。

后来工具越来越多,一时半会儿数不过来。但我越来越确定一件事:工具本身不是最重要的。截拳道有句话叫"以无法为有法,以无限为有限"[5]——先扎实学会各种招式,但真正交手的时候,死守招式反而会束手束脚,高手是根据对手随机应变,像水一样流动。放到 agent 上也是一个道理:一个 agent 说到底无非是模型、规则和人格设定、能稳定复用的 skill、再加上能接入更多工具的 MCP。想清楚这几层,换哪个软件都能很快上手,不必把时间都耗在"这个月又出了什么新工具"上。这套框架我会留到第二章再展开讲。

这本书为什么从"认识自己"讲起,而不是从商业模式讲起,也是同一个道理。把时间花在自己不擅长的事情上是事倍功半,做自己擅长的事情才能事半功倍。你得先知道自己是什么样的人、适合承担什么角色,才谈得上让 AI 去补你不擅长的那部分。

之所以叫 Adventure,是因为整个过程很像玩一款游戏。开局你先捏一个角色,做完新手村的任务,才会对这个角色、对接下来的玩法有代入感。给公司取名字、搭网站、做出第一个产品、面对第一个客户,都像是一关一关往前打。等你真的面对过足够多的客户,你对市场的理解会变,你也会换一套打法,像游戏里到了新阶段要换装备一样。

所以这本书想做的事情,更接近教你怎么把车开稳、开安全,至于你开出去之后是去越野、去赛车、还是去长途自驾,不是这本书要管的事。我们不教哪个赛道能赚钱,也不教怎么在某个赛道里赚钱——那是你自己上路之后才会遇到的问题。

我希望的是,读完这本书,你不会再是那种一头扎进某个"商机"里的状态。你会先知道自己是谁,知道怎么和 AI 一起把名字、风格、生产流程这些基础的东西一件件搭起来。至于接下来要做什么生意、面对什么市场、能走多远——那是离开新手村之后的事了。
